# ⚠️ 重要工作原则 - 不要自以为设计

## 2026-02-19 的教训：key 重新分配 bug

### 事件
实现 Zotero 同步功能时，本地生成的 key 总是被云端重新分配：
- ❌ 盲目清理字段，删除了 `key` 和 `version`
- ❌ 假设 key 格式问题，花大量时间研究算法
- ❌ 没有打印实际发送的数据
- ❌ 没有集成测试验证 key 保留行为

**根本原因**：API 要求 `key` + `version` 一起发送，我们却删除了它们。

### 关键教训

1. **永远不要盲目删除数据** 🔒
   - 清理/序列化逻辑中要特别小心
   - 必须区分"可以删除"和"绝对不能删除"的字段
   - 关键字段要有保护机制

2. **关键字段必须保护** 🛡️
   ```typescript
   const CRITICAL_FIELDS = new Set(['key', 'version', 'itemType']);
   // 这些字段 NEVER 被删除
   ```

3. **假设必须通过数据验证** 📊
   - "我认为"不如"我看到"
   - 打印实际发送的数据
   - 用数据验证假设，不要猜测

4. **集成测试是必须的** 🧪
   - 单元测试无法发现跨层问题
   - 端到端测试才能验证真实行为
   - 关键流程必须有测试覆盖

## 📋 工作原则（必须遵守）

### 当被要求调研或实现功能时

1. **先找原始资料/代码** 🔍
   - 搜索工作区现有实现
   - 查找官方文档/规范
   - 寻找实战验证的代码
   - 不要跳过这一步！

2. **仔细阅读理解** 📖
   - 不跳过细节
   - 理解"为什么这样设计"
   - 注意关键差异点
   - 做笔记记录要点

3. **验证理解** 🧪
   - 对比多个来源
   - 实际测试验证
   - 确保理解正确
   - 不要假设

4. **最后才实现** 💻
   - 基于理解，不是推测
   - 复用现有代码（如果可能）
   - 保持兼容性
   - 测试验证
